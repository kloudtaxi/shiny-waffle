## Sovera - Product vs Platform

The simplest distinction is:

**A product solves a problem. A platform enables solutions.**

### **Product vs. Platform**

|  |  **Product**  |  **Platform**  | 
|---|---|---|
|  **Primary purpose**  |  Deliver a specific outcome  |  Enable many outcomes  | 
|  **Who uses it?**  |  End users / customers  |  Users **and** developers/builders  | 
|  **Scope**  |  Defined use cases  |  Extensible capabilities  | 
|  **Experience**  |  Opinionated, packaged  |  Configurable, composable  | 
|  **Value**  |  “Do this for me”  |  “Build/do whatever you need”  | 
|  **Growth**  |  More users / more usage  |  More use cases, apps, integrations, developers  | 
|  **Example**  |  Salesforce CRM  |  Salesforce Platform  | 
|  **AI example**  |  AI sales assistant  |  AI infrastructure + agents + models + data + tools  | 
### **A useful mental model**

Think of a **product as a house** and a **platform as the infrastructure and building system**.

A house is designed for a particular purpose: *live here.*

A platform provides foundations, utilities, interfaces, and building blocks from which many different things can be built.

---


### **The litmus test**

Ask: **“If I removed the current application/use case, would the underlying technology still be useful for building something else?”** If **yes**, you’re probably looking at a platform. 
For example: **Product:** “Ask questions about your sales data.” versus **Platform:** “Connect enterprise data, understand its semantics, retrieve context, invoke models, orchestrate agents, and build AI applications.”
The first has a **job to be done**. The second provides the **means to build many jobs-to-be-done**.
