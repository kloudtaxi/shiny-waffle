**Global rule (README.md:3-8)**: "One fresh KB per run" (`每一组一个新库`). Reason: three consecutive tuning rounds ran on the same KB, which still carried class refinements from earlier rounds ("already correctly typed as pharmacy" appeared in rejection reasons); rounds 2-3 were not comparable to round 1 and were nonetheless used to change code twice. Re-using a KB "saves minutes, buys a whole stretch of invalid conclusions". Exceptions are deliberate and documented (recall.mjs `--kb`, warm-KB second-batch runs).

**Also global**: the bench needs a running `utopia-server`, a writable Postgres reachable by `BENCH_PSQL` (a `docker exec … psql` command by default), a workspace with chat + embedding models configured (`README.md:17-18`). The scripts sign in as a throwaway local bench account. Several scripts promote that user to admin by SQL (`UPDATE users SET is_admin=TRUE`, `run.mjs:135`, `temporal.mjs:127`).

## 1. Type resolution — `run.mjs`

1. **Measures**: after ingestion, does each entity end up in the right class of the imported ontology (schema.org pack, 965 classes), and does "type resolution" (`POST /kbs/{id}/ontology/type-resolution`) refine it correctly without touching entities that should stay untyped?
2. **Corpus** (`corpora/`):
   - `pharma.json` (zh, 5 short docs, ~2.3 KB JSON) and `pharma-en.json` (sentence-by-sentence English translation); `tech.json` / `tech-en.json` (zh/en, 5 docs). Hand-written synthetic, committed. Entities deliberately recur across docs (`README.md:22-24`). Added in the GLiNER comparison: English translations (`README.md:286-289`).
   - `ai-timeline.json` (15 Wikipedia articles on AI companies, 278 KB) and `ai-timeline-ends.json` (6-article subset chosen for density of "ending" wording: 25 of 60 chunks vs 14% corpus-wide). Source: MediaWiki `prop=extracts`. Licence field in the file: "CC BY-SA 4.0 (attribution-share-alike, differs from the repo's main licence)". Committed. The file's own note warns these companies are heavily in model training data, so they suit demos, "not accuracy benchmarks (you measure recall of memorised text)".
   - `holmes.json` (6 Sherlock Holmes stories, 308 KB, Project Gutenberg #1661, public domain; "demo and entity-resolution benchmark; not a typing benchmark, the model has read it"). `sotu-tr.json` (3 Theodore Roosevelt State of the Union addresses, 352 KB, US government work, public domain). Neither has a truth file in `truth/`.
   - Language: pharma/tech zh+en; Wikipedia ones English.
3. **Truth**:
   - `truth/pharma.json` 22 entities, `truth/tech.json` 16 (zh), `pharma-en.json` 22, `tech-en.json` 16. Hand-written. Format: key = a substring of the entity name (extracted names vary run to run); value = list of acceptable class keys, any hit counts. **Empty array = no matching class in the ontology, correct behaviour is to leave the entity untouched** (`README.md:22-26`).
   - `truth/ai-timeline.wikidata.json` (643 entities) and `truth/ai-timeline-ends.wikidata.json` (191 entities): "answer sheets not touched by hand" (`README.md:27-33`): for each entity in the Wikipedia corpus, take its Wikidata P31 (instance of), map via `p31-to-classes.json` to schema.org classes. Generated by `make-truth.mjs`; raw material in `*.wikidata.raw.json` (QIDs, P31, anchors). File header: "Generated ... do not edit by hand — fix the mapping or refetch". Match mode `exact` (full name). An entity that reaches no anchor class is omitted ("if unknown, don't guess"). The human judgement is confined to the mapping table. Independent of Utopia's output (Wikidata); but the *class vocabulary* is schema.org.
   - Truth can be wrong (`README.md:261-265`): first run wrote `心血管健康论坛` ("Cardiovascular Health Forum") too narrowly as `business_event|event_series`; the system's `conference_event` was right. Rule: fix the key after seeing results, but only with a written reason, otherwise the key becomes a record of what the system said.
4. **Metric** (`README.md:248-259`): hit = an acceptable class **or a subclass of it** (class hierarchy from the KB; anchors like organization, place are answered more specifically, e.g. research_organization, city). `for_review` (pending human review) counts as a **miss** ("counting it as a hit books human work to the machine"). `absent` = in truth but never extracted (not a resolution error; own column). `wronglyChanged` = entity that should be untouched but was re-typed (baseline "untouched" state is `type_id IS NULL`, printed `-`, `run.mjs:30-36`). `score.tiers`: `auto` (auto-landed tier vs truth) and `review` (what blind acceptance of the review tier would give). `prompt_tokens_est` = ontology-section chars / 4.0 (measured 4.0 chars/token, 377,735<->81,855 and 396,716<->99,041); it measures ontology size, not the whole prompt. Hand truth matches by substring, generated truth by exact name.
5. **Recorded results**: the README gives **no standalone table for run.mjs**; the only numbers are the GLiNER comparison, which contains Utopia rows (`README.md:272-338`), measured 2026-09-04, schema-org pack (965 classes), one fresh KB per corpus, DeepSeek-V3.2 extraction. Cells are "found" (answer entities extracted) and "type correct" (denominator = found AND has a class in truth, computed per row, so read both columns).

   Chinese:

   | | pharma found | pharma type correct | tech found | tech type correct |
   |---|---|---|---|---|
   | Utopia, at extraction | 22/22 | 11/20 | 15/16 | 3/13 |
   | Utopia, after type resolution | 22/22 | 16/20 | 15/16 | 10/13 |
   | GLiNER, only answer classes | 18/22 | 16/17 | 12/16 | 10/10 |
   | GLiNER, 965 classes in 39 batches | 20/22 | 9/19 | 13/16 | 5/11 |
   | GLiNER, 965 classes at once | 0/22 | – | 0/16 | – |

   English:

   | | pharma found | pharma type correct | tech found | tech type correct |
   |---|---|---|---|---|
   | Utopia, at extraction | 21/22 | 17/20 | 15/16 | 9/13 |
   | Utopia, after type resolution | 21/22 | 19/20 | 15/16 | 12/13 |
   | GLiNER, only answer classes | 22/22 | 17/20 | 13/16 | 11/11 |
   | GLiNER, 965 classes in 39 batches | 22/22 | 13/20 | 16/16 | 4/14 |

   Timing: GLiNER ~1 s per corpus with 20 labels, ~40 s batched, ~70 s with all 965; Utopia 40-100 s per corpus (model queueing). README's reading: GLiNER is accurate/fast with few candidate classes, collapses to under half type-accuracy with the full ontology, goes blind when 965 labels fill its window; Utopia is notably better in English than Chinese (pharma at extraction 11/20 vs 17/20; class descriptions in the extraction prompt are English). Conclusion: not a replacement, a candidate-prescan idea, "experiment not yet done". Noise estimate: 22 and 16 items — each item is ~5-6 points; no SD given.
6. **Coupling (Utopia-specific)**: `run.mjs` creates a KB (`POST /workspaces/{ws}/kbs`), imports an ontology (`POST /kbs/{id}/ontology/imports`, TTL), sets `UPDATE knowledge_bases SET auto_extend_ontology=FALSE`, ingests (`POST /kbs/{id}/ingest`), polls `documents.graph_status='done'` and `chunks.extracted_at`, runs `POST .../ontology/type-resolution`, then reads results by SQL: `entities`, `entity_types`, `entity_type_parents` (recursive CTE for subclass check, `run.mjs:296-301`), `entity_retypes` (`:341`), `relation_types`, `relation_type_domains`. Adapter needed: a function returning `[(entity name, class key)]` plus a class hierarchy (parent map). Everything else (corpus, truth, substring match, subclass rule) is portable. Ontology vocabulary is schema.org snake_case keys (`government_organization`, `medical_trial`); a foundation with a different type system needs its own mapping from those keys.
7. **Warnings**: one fresh KB per run; truth edits only after results with written reason; `for_review` counts as miss; 22/16-item sets are tiny.

## 2. Recall — `recall.mjs` (+ `fetch-sec-filings.mjs`, `judge_open.mjs`, `figures.mjs`)

1. **Measures**: of the facts a human reads in a document (amounts, capacities, terms, vote counts, job titles), how many are present in the graph — "present", not "landed on the ontology" (`recall.mjs:1-10`; `README.md:48-58`).
2. **Corpus**: 4 real SEC filings from NVIDIA's EDGAR (`fetch-sec-filings.mjs:DOCS`, base `https://www.sec.gov/Archives/edgar/data/1045810`): an 8-K acquisition announcement (2026-09-02, "one sentence, three numbers"), a multi-party press release exhibit (2026-08-17; 7 parties, 4 executives with titles), the Q2 FY27 earnings release (financial tables), and a vote-results 8-K (2026-06-24; 21 header-less tables, 10 directors x 4 vote types). English. **Fetched at run time via `curl`, not committed** (filings are SEC public documents but copyright belongs to the filers; `fetch-sec-filings.mjs:12-15`, `.gitignore` entries). Needs `SEC_USER_AGENT`. The files do not exist in the repo checkout (`corpora/nvda-public-docs/` absent). Note: filings are dated 2026.
3. **Truth**: `truth/nvda-public-docs.json`, **52 items, hand-written by reading the filings** ("a table a person listed from reading the source", `README.md:52-54`). Kinds: 39 `value`, 12 `edge`, 1 `predicate`. By doc: 19 earnings release, 15 Aug exhibit, 11 Sep-02 8-K, 7 Jun-24 8-K. Item shapes: `value` -> `value_any: ["11.9"]`; `edge` -> subject/object name lists; `predicate` -> `predicate_any`. Independent of Utopia's output. Deliberately NOT based on Utopia's `extraction_drops` / `ontology_misses` signal tables because those "only see extracted-but-not-landed, not never-extracted" (`README.md:54-58`).
4. **Metric** (`recall.mjs:128-170`): per item, flatten all current facts of that doc into `subject | predicate | object | valid_from | qualifiers` and test: `value` = any `value_any` is a substring (case-folded; also whitespace/hyphen-squashed, "8 IT-GW" == "8-IT GW"); `edge` = some fact has subject and object names matching in either direction; `predicate` = some predicate contains one of the strings. Score = hits/52 overall and per doc and per kind. **Noise: "52 items, ~90% hit rate, one SD ≈ 2.7 items. A one- or two-item difference in a single round is not evidence; re-run the same code first"** (`README.md:82-84`). Structural signals to watch instead: `object_missing` counts, whether a whole class (e.g. "titles of four executives") arrived. Companion `judge_open.mjs --sample 200`: judge model reads source text and labels sampled open statements stated / misworded / not_stated; threshold from ADR 0044: not_stated <= 2% (`judge_open.mjs:11,189`). Judge endpoint `BENCH_JUDGE_BASE/KEY/MODEL`, else the workspace chat model (then judge == extractor; discount the number). `figures.mjs`: share of money/percent/unit numbers in paragraphs that appear in no statement of that chunk.
5. **Recorded results** — 2026-09-09, dev @ cb2bab7 + nine changes, DeepSeek-V3.2 + bge-m3 (`README.md:86-100`):

   | round | change | score |
   |---|---|---|
   | baseline | – | 33/52 |
   | r1 | literal-value channel opened | 29/52 (regression) |
   | r2 | + tables keep rows/columns + relation floor + subject fallback | 44/52 |
   | r3 | + role rule + empty-column trimming | 43/52 |
   | r4 | + empty header yields | 44/52 |
   | r5 | + "a roster is a roster" | **49/52** |
   | r6 | no code change, rerun | **49/52** |

   r5 and r6 missed different items (empty intersection); the remainder is sampling noise. r1's regression was the most valuable find: after literals were allowed, subject resolution (stricter than the relation channel) dropped 113 facts in one round. No judge_open or figures numbers are recorded in the README.
   **Main adds** (`main:README.md:~60-125`): `--known shown|empty --out runs/588` labels and `--table runs/588` (mean ± SD per group, Jaccard overlap of (s,p,o) fact sets) to measure the effect of `UTOPIA_EXTRACT_KNOWN_IN_PROMPT=false` on recall (#588); per-doc shape (chunks, facts, entities, cross-chunk re-recognised entities, pairs queued for adjudication, `extraction_drops` by reason, seconds to last chunk); incomplete runs are flagged `complete:false` and excluded from group means; settle-wait for background jobs. No numbers for #588 are in the README.
6. **Coupling**: `recall.mjs` is deeply Utopia: SQL `facts JOIN fact_evidence JOIN documents JOIN entities JOIN relation_types`, predicate = `coalesce(rt.key, fe.proposed_predicate)`, `fact_qualifiers` (edge attributes), **`statement_qualifiers`** (open-statement qualifiers, role=value), **`time_mentions`** (verbatim time words for open statements), `f.invalidated_at IS NULL`; it clears state with `DELETE FROM facts/entities/extraction_drops/ontology_misses`, resets the ontology to "pack-install time" (`DELETE FROM relation_types ... created_at > packTs`), flips `knowledge_bases` flags (`auto_extend_ontology`, `auto_type_resolution`, `materialize_inferences`, `governance`), resets `chunks.extracted_at`, deletes jobs, and re-triggers extraction (`POST /documents/{id}/...`), and requires a KB with schema.org pack + embeddings (2,500 vectors, ~20 min; `README.md:78-80`). The truth file and the match rules are portable: an adapter only needs to return, per document, rows `(subject, predicate, object, date, qualifier-text)`. `judge_open.mjs` reads `layer='open'` facts and `llm_settings` (judge defaults to the workspace model).
7. **Warnings**: this bench deliberately does NOT use a fresh KB (`--kb` needs ontology+vectors already installed; everything else is wiped each round, auto-extend relations grown in the previous round are deleted or they leak into the next prompt); disable auto-extend and type-resolution within a round; same conditions each round; 52 items => ±2.7 SD; judge == extractor inflates precision.

## 3. Temporal — `temporal.mjs`, `temporal/corpus.json`, `temporal/questions.json`

1. **Measures** (`README.md:342-350`, `temporal.mjs:1-30`): answering "as of date X" correctly **after facts have changed**, on two axes. World axis (`at`): what was true then. Record axis (`as_of`): what we believed then. Authors justify it: other memory benchmarks (LongMemEval, DMR) test conversational recall, none asks "who managed this project in March 2023" when the answer changed twice; the repo's only citable number before this was Ontology2SQL on BIRD Mini-Dev.
2. **Corpus**: `temporal/corpus.json`: fictional company (Meridian Systems, Project Aurora, Platform Group; people Zhang San, Li Si, Zhou Qi, Lin Zhao, Wang Wu), English text, deliberately blunt sentences ("one fact per sentence, full dates, full names"), 3 waves of documents, plus 3 classes and 6 uniqueness axioms (functional/inverse-functional declarations). Committed. Fictional so model memory cannot help. Wave 1 baseline; wave 2 brings handover memo, salary correction, one document deletion; wave 3 more. Record-axis timestamps are taken from the real clock after each wave finishes (not by faking the clock), so tests the actual ingest/extract/delete path.
3. **Truth**: `temporal/questions.json`, **37 questions** (23 world-axis, 14 record-axis), all hand-written; `known_gap: true` flag on 2 (excluded from the main score). Each: `id, axis, at|as_of, subject, expect, not[], ask` (natural-language form for the chat run). Independent of Utopia's output.
   Scenarios (`README.md:397-408`): three-term relay A->B->C (uniqueness closure twice); salary correction 28000 -> 32000; hire earlier than the document that states it; deletion of a document (retraction visible on record axis, invisible today); human edits a fact's start (#311); human merges two spellings "L. Si" -> "Li Si" (#337); year-only precision; "no longer holds, date unknown" (`valid_to_precision = unknown`, known gap #345); a fact with no start read as "forever" (known gap #352); **three questions whose correct answer is empty** (before project start, before hire, after retraction).
4. **Metric**: for the subject entity at that moment, does `expect` appear among facts attached, and is any of `not` present? Predicate names are ignored (works_for vs employed_by) because the bench measures time not vocabulary (`README.md:375-377`). `expect: null` = nothing should hold. `absent` (entity not extracted) is a separate bucket. Main score excludes known gaps. `--chat` re-runs through chat with tools; only normalisation: thousands separators (28,000 -> 28000). Dev scoring flags a negation containing a `not` name as wrong (known weakness); **main changed this** (2026-09-28): the answer must contain `expect` and none of `not` may appear *before* it; `expect:null` questions still fail if any `not` name occurs. Noise: ledger path deterministic given the same KB (apart from extraction variation); chat path "same question differs between two runs, ±2 questions" (`README.md:490`). Also named noise source: unresolved same-name entities (Meridian Systems / Project Aurora split in 2-3 entities); questions take the first name match.
5. **Recorded results** — 2026-09-05, dev @ 619061e, DeepSeek-V3 + bge-m3 (`README.md:417-424`):

   | config | main score | world axis | record axis | known gaps |
   |---|---|---|---|---|
   | uniqueness axioms declared | **35 / 35** | 21 / 21 | 14 / 14 | 0 / 2 |
   | ontology grows itself (`--no-declare`) | **28 / 35** | 15 / 21 | 13 / 14 | 1 / 2 |
   | grows itself, declare after ingest and reconcile (`--no-declare --reconcile`) | **34 / 35** | 21 / 21 | 13 / 14 | 1 / 2 |

   Cause of the 28/35: auto-closing runs on `functional` / `inverse_functional`, which are never auto-inferred; so without declarations all three leaders stay open ("three people lead one project at once"; that is "what a new user's KB looks like out of the box", #341). Declaring every candidate made it worse (set `leads` subject side and `works_for` object side as functional; Li Si's Aurora closed by Helios) — "candidates are evidence, not verdicts". Earlier versions (25 questions: 25/25 vs 15/25; 36 questions: 36/36 vs 29/36) are in git history. Must wait for the job queue to drain before recording wave timestamps.

   Chat path (`README.md:464-496`): **28 / 35** after fixes #349 (model sees literal values) and #350 (tool surface gets `as_of`); before it was 24/37 (7 record-axis not askable, 6 salaries invisible). Record axis 9/14 (was 7/14). The 7 failures: 3 = scorer cannot read negation; 2 = model emitted tool-call tokens as text (DeepSeek-V3 via SiliconFlow, rerun fixes); 2 = "before ..." questions (model has to find the moment in `changes`; `changes` only prints to the day, #351). An earlier "8/37" was void: probe read the wrong SSE field (`.delta` not `.text`) so every reply was empty and empty replies satisfied `expect:null`; now empty reply = `error`, not scored. Known asymmetries: attribute facts (salary, title) come from the entity panel API, which only has `as_of`, no `at`, so the script filters `valid_from/valid_to` itself; `at` absent = unfiltered, `as_of` absent = now; "no longer holds, date unknown" read as still true.
   **Main adds**: reported `via` (graph / text / both / none) and "answered through the graph" / "only through the graph" counts; citation clickable check (#935); `lib` tests. No new temporal numbers in the README.
6. **Coupling**: ingestion `POST /kbs/{id}/ingest {filename, content, doc_time}` with `doc_time` driving valid_from; declared ontology via `POST /kbs/{id}/ontology/entity-types` and `.../relation-types` (including uniqueness flags) and `GET /kbs/{id}/ontology/uniqueness` + `PATCH .../relation-types/{id}` + reconcile; `DELETE /documents/{id}`; `PATCH /kbs/{id}/facts/{id}` (human edit of a start); `POST /kbs/{id}/entities/merge`; reads via `GET /kbs/{id}/graph/neighborhood?at=&as_of=` and `GET /kbs/{id}/entities/{id}` (attribute facts); SQL on `documents`, `jobs`. Portable: `corpus.json` waves (documents + doc_time), `questions.json`. An adapter would need: (1) ingest documents in 3 waves with a document timestamp, (2) a way to apply the post-ingest operations (delete a doc, correct a fact start, merge two entities), (3) query "facts about entity E, true at world time T, as the system knew at record time R".

## 4. Identity — `identity.mjs`, `corpora/identity/`, `truth/identity.json` (not described in the README)

The README does not mention this bench; everything below is from the script header and the files (`identity.mjs:1-20`; ADR "0041 step 0").
1. **Measures**: two error types at once: homonyms wrongly merged (two "Zhang Wei", two "technology centres", "Probe No.1 vs No.2") and aliases wrongly split (rename, abbreviation, Chinese vs English name).
2. **Corpus**: `corpora/identity/d00..d11-*.txt`, 12 tiny Chinese documents (82-244 bytes each; one English), invented institute story (East Sea Marine Research Institute renamed Lanhai Research Institute 2021-06-01; probes 海探1 / 海探2 / Haitan-2; two namesake Zhang Weis in finance and engineering; Li Na / Li Na; two look-alike technology centres). Committed. Ingest order and per-document `doc_time` in `truth/identity.json` `docs`.
3. **Truth**: `truth/identity.json`: 8 real-world entities (INST, P1, P2, ZW_FIN, ZW_ENG, LN, TC_LH, TC_LJ), 21 anchors (document + quote substring + type [+ role / other_has] -> which real entity), 3 look-alike pairs (ZW_FIN/ZW_ENG, TC_LH/TC_LJ, P1/P2). Hand-written; independent of Utopia.
4. **Metric**: names are **not** used in scoring. Each anchor is resolved to a system entity id (via merge chain survivors); anchors compared pairwise: same id and same truth = TP; same id different truth = FP (false merge); different id same truth = FN (false split). Reports precision, recall, F1, false_merges, false_splits, per-entity fragmentation, look-alike pairs merged?, `missing` anchors, `split_in_doc`, pending review items, entity count. **Insertion order is itself measured**: each run builds one forward-order KB and one reversed-order KB and reports the fraction of anchor pairs judged differently (`orderDisagreement`). No threshold, no noise estimate in the files.
5. **Recorded results**: none in the README or the script (no results table found in the bench dir; git log shows only commit 4363ac3 "0041 records that a name is a claim about an entity (#663)"). So no Utopia baseline here — we would have to run it.
6. **Coupling**: KB created with the ontology frozen (auto-extend, type resolution, governance, materialisation all off), ontology types from `truth.ontology` posted via `POST /kbs/{id}/ontology/entity-types` and `.../relation-types`; ingest per doc; waits on `jobs`/`documents.graph_status`; resolves anchors with SQL over `facts`, `fact_evidence`, `documents`, `entities` (`merged_into` chain, recursive), `entity_types`, `resolution_reviews` (`identity.mjs:150-172, 248`). Adapter: for each anchor, return the canonical entity id of the entity in doc D whose supporting quote contains Q and whose type is T. The score function (`score(kb)`, `identity.mjs:206-262`) is ~50 lines of pairwise counting and trivially portable.
7. **Warnings**: ordering matters; frozen ontology; names don't count.

## 5. Typed graph (Re-DocRED) — `typed.mjs`, `fetch-redocred.mjs`

## 6. Governance (duplicate adjudication) — `govern.mjs`

1. **Measures** (`README.md:102-130`): whether the governance agent resolves duplicate-entity suggestions correctly and how many remain waiting for a person.
2. **Corpus**: 8 interlocking Wikipedia articles in `corpora/ai-timeline.json` (OpenAI board crisis, OpenAI, Anthropic, DeepMind, Mistral, Inflection, SSI, ChatGPT; see `truth/ai-timeline.duplicates.json` `docs`). CC BY-SA 4.0, committed. English.
3. **Truth**: `truth/ai-timeline.duplicates.json`: every duplicate pair the resolver raised on one governed import (615 pairs, **411 distinct name pairs**), **hand-labelled 2026-09-07** from each side's facts and source passages: `same` 110, `different` 296, `unknown` 5 (one side has no facts and the bare name cannot decide, e.g. "judge", "Time"; people can't either). `different` covers versions, divisions, subsidiaries, or a sentence that merely contains the name. Keyed by two names, side- and case-insensitive; a name pair that repeated is labelled only if all repeats had the same answer. Labels depend on what Utopia's resolver proposed in that import (so the pair set is Utopia-generated, but the verdicts are human).
4. **Metric**: `decided_on_its_own` (agent decided itself), `agreed_with_labels`, **`wrong_merges`** (the most important: a bad merge needs a human to revert), `left_for_people` (with how many labels say merge vs split), `unlabeled` (names from this import not in truth; neither right nor wrong; non-zero is normal since re-extraction varies names). No SD/noise estimate. No explicit pass threshold in the script.
5. **Recorded result** (`README.md:128-129`): 2026-09-06 on the same corpus, with the gate still "no precedent, no merge": governance off -> the old adjudicator auto-merged 146 and left 50 for people; governance on -> merged none, left 200. That number caused ADR 0025 decision 4's revision. No other tables.
6. **Coupling**: sets `knowledge_bases.governance`, `ontology_packs: ["schema-org"]`, inserts `jobs(kind='govern')`, reads `resolution_reviews`, `agent_decisions`, `entities`, `entity_merges`; `--reset` rewrites tables directly with a SQL block replicating `revert_merge` (`govern.mjs:104-136`). Portable: only the label file (411 pairs). Adapter: for each name pair, system says merged / kept separate / undecided.

## 7. Mappings (database-schema -> business metrics) — `mappings.mjs`

1. **Measures** (`README.md:131-168`): does the "explore" step that proposes business definitions (metrics) from a DB schema produce correct ones; how many does it miss; and how many are wrong-but-runnable.
2. **Corpus**: `schemas/tpch.sql` (254 lines) + `tpch.comments.sql` (70) — TPC-H 8-table schema with rows made by `generate_series` + fixed `setseed` (not TPC's data generator; "explore reads only the schema, gold and proposal run on the same rows"); `schemas/wide.sql` (114) + `wide.data.sql` (146) + `wide.comments.sql` (63) — a flattened Chinese e-commerce order table `dw.dwd_ord_dtl` built by the authors with deliberate traps (amounts in cents, jargon column names, business conventions not in column names, look-alike columns `amt_total` vs `amt_pay`, trap columns such as integer keys and constant `ver`). Committed SQL. Column comments are a separate independent variable (TPC-H has none, real DBs do): run with and without (`--no-comments`).
3. **Truth**: `truth/tpch.mappings.json`: 24 metrics (gold SQL), 3 `plausible` extra definitions, 16 dimensions, 9 keys, 11 traps; **definitions copied from the TPC-H spec's 22 queries** (e.g. revenue = `sum(l_extendedprice*(1-l_discount))`) — "not ours: defining the metric ourselves would measure self-consistency" (`README.md:157-160`). `truth/wide.mappings.json`: 6 `conventions` (text), 18 metrics each with `gold`, `naive` (what a schema-only reader would write), `note`, `summary` (Chinese description), 16 dimensions, 15 traps. Hand-authored; independent of Utopia.
4. **Metric**: scoring is by **numbers, not names**: run each proposal and the gold SQL on the same rows; same number = same metric. Columns: `covered` (truth items computed by any proposal), `right` (runnable proposals matching some truth), **`wrong`** (runnable, matches no truth, with its number and nearest truth — "the one to watch": only the plausible-but-wrong ones are dangerous and this column is the sole basis for whether #504 can default on), `broken` (cannot run), `traps_hit` (proposals landing on trap columns: integer FK sums, constant columns like `o_shippriority`, free-text dimensions). Equality uses `lib.mjs` `same()`; `roughly()` (two orders of magnitude looser) for the ask bench.
5. **Recorded results**: no standalone score table for mappings in the README. Related numbers are in the ask section below (convention ladder on wide; recall@8).
6. **Coupling**: needs a second Postgres database (`bench_<corpus>`, on the local Postgres), registers a data source `POST /admin/data-sources`, grants it to the workspace (`PUT .../grants/{ws}`), mounts it on the KB (`PUT /kbs/{id}/data-sources/{ds}`), triggers `POST /kbs/{id}/data-sources/explore`, waits for `jobs.kind='explore_mappings'`, and reads `concept_mappings` JOIN `entities`/`entity_types` (`mappings.mjs:127-150`). Portable: the two SQL schemas, comments, gold/naive SQL, the number-equality rule. Adapter: system output as a list of `(name, SQL expression or query)`; the scorer's run-and-compare step is generic.
7. **Warnings**: new KB each run, because `propose` has `ON CONFLICT ... WHERE status='proposed'`, so a second exploration inherits rows of the first ("second run's score is not the second run's"). `--conventions` writes data conventions before exploration (prompt reads them).

## 8. Ask (text-to-number, end to end) — `ask.mjs`

1. **Measures** (`README.md:170-227`): a person asks in words, does the number that comes back match gold? Not implied by the mappings bench in either direction.
2. **Corpus / truth**: the same two SQL databases. Questions in `truth/tpch.questions.json` (24, English) and `truth/wide.questions.json` (18, Chinese), keyed by the metric id in the matching `*.mappings.json`; worded "like someone who has never seen the schema: no table names, no column names, no SQL". Hand-written.
3. **Metric**: judged from two things: the assistant's final text, and the SQL the model actually ran (`tool_exchange`; SQL short enough to survive truncation). `sql_right`: re-run its SQL and compare with gold; `answer_right`: the printed number is the number. They can diverge (right query, wrong unit/rounding/paraphrase). Equality is `roughly()` ("about 863 million" == 862793473.48). When a question fails, the script says whether the needed definition had a confirmed mapping (`mapped` / `UNMAPPED`) -> loop: run, inspect failures, unmapped = coverage problem, mapped-but-wrong = prompt/tool/definition problem. `--seed` writes gold as confirmed mappings (upper bound), `--confirm` confirms what exploration proposed (product path), `--recall K` measures retrieval only (is the right definition in top K, seconds), `--parallel N` (a question takes 2-6 model turns, serial half an hour).
4. **Recorded results** (`README.md:185-196`; no date, commit or model given for these): with `--recall 8`, 45 definitions across both sources in one KB: when the stored description is a placeholder, wide recall@8 **13/18**, ask **15/18**; with real descriptions (truth `summary`, in the question's language): recall **18/18**, ask **18/18**; tpch recall **23/24** and ask **24/24** in both cases. "The embedded one-line description is the entire retrieval; the reranker has no miss to fix." Convention ladder on wide (chat right): nothing 2/18; exploration-generated descriptions 2/18; descriptions + 6 conventions 11/18; conventions + 18 definitions written as one page of prose, via retrieval 14/18; 27 confirmed definitions in the prompt 17/18. Exploration coverage: no conventions 0/18, with conventions 3/18 (the wrong ones all carried `is_test != 1` but picked the wrong column). #520 first round: the model alone, from the schema doc, answered 23/24 TPC-H (so TPC-H cannot show the semantic layer's value; hence the `wide` corpus, `schemas/wide.sql:1-9`).
5. **Coupling**: SQL on `conversation_messages.tool_exchange`, `conversations`, `concept_mappings` (insert/update confirmed mappings), `entity_types key='metric'`, chat endpoint, `GET /kbs/{id}/mappings/relevant?q=&k=`. Questions + gold SQL fully portable; the two Postgres schemas are standard.

**Direct answers to "baseline AND corpus?"**
- Strongest portable assets: `temporal/` (corpus+questions), `corpora/contracts/` (manifest + QUESTIONS), `corpora/identity` + `truth/identity.json`, `truth/ai-timeline.duplicates.json`, `truth/nvda-public-docs.json`, `corpora/redocred-*` + `truth/redocred-*`, the two SQL schemas + gold SQL.
- All hand-made truth: pharma/tech (zh+en), nvda-public-docs, temporal questions, identity anchors, contracts QUESTIONS, duplicates labels (hand verdicts), tpch/wide mappings + questions, redocred-typed questions, timewords (main). Not hand-made: Wikidata-derived (`*.wikidata.json`), DocRED labels (Re-DocRED human annotation, third-party).
- Baseline numbers exist for: recall (33->49/52), temporal (35/35, 28/35, 34/35; chat 28/35), typed graph (many tables), contracts (5-12/18), governance (146/50 vs 0/200), GLiNER comparison, ask (24/24, 18/18). **No recorded Utopia baseline** for: identity bench, run.mjs standalone, mappings standalone, competency, judge_open/figures.
- Caveats for using Utopia numbers as a baseline: models differ by run (DeepSeek-V3/V3.2, gemini-3.5-flash, claude-haiku-4-5, deepseek-flash), commits differ, embeddings mostly bge-m3, often Chinese-language prompts for zh corpora; the README itself says single-round differences are within noise (recall SD ≈ 2.7/52; contracts ≈ 3/18; chat ±2 questions; typed judge ±5 points at n=200).
- Our stack (Docling, langextract, gpt-6-luna, text-embedding-3-small): the committed corpora cover Chinese and English; for a B2B English use-case, only temporal (English), contracts (English), recall (English), Re-DocRED (English), duplicates (English), and the TPC-H questions (English) apply directly. Identity, mappings-wide, ask-wide, timewords are mostly Chinese and need translation or new English counterparts.
- Does it need a database? All Utopia scorers shell out to Postgres through `BENCH_PSQL`; only `lease_bench.py`, `competency.mjs`, `ask.mjs` (partly) and `temporal.mjs` (partly) can score through the HTTP API alone. For a different foundation, expect to re-implement the data-access layer (a few dozen lines per bench).
