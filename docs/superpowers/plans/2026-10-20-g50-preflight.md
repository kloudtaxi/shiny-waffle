# G-50 Pre-flight Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a `lab/preflight/` package that checks a run folder before its first paid call (inputs,
fingerprint, settled, agent context), writes a record, guards spend across processes, and has a
Textual operator app on trial.

**Architecture:** collectors do the I/O (questions and evidence, git, the foundation, the runner's
own probe) and run concurrently. Checks are pure functions of what the collectors observed, the
config and the baseline record. An engine ties them together and writes write-once records. Two
front ends share the engine: a plain CLI and a Textual app.

The spend guard is a separate module the runners use. It holds an `fcntl.flock` over the run
folder's recorded costs and live reservations.

**Tech Stack:** Python ≥3.11, pydantic 2 (config and records), PyYAML, stdlib `subprocess`,
`fcntl`, `concurrent.futures`. Textual 8.2 and textual-serve 1.1 for the app. pytest, mypy strict,
ruff.

**Spec:** `docs/superpowers/specs/2026-10-20-g50-preflight-design.md` (4afc70f, approved by the user
on 2026-10-20). Section references (§) below are to the spec.

## Global Constraints

- Python target 3.11 (mypy `python_version = "3.11"`, ruff `target-version = "py311"`); line length
  100; mypy `strict = true`, tests included; ruff `select = ["E", "F", "I", "B", "UP", "N", "W"]`.
  Run `uv run ruff format` on every new file.
- **Nothing outside `lab/preflight/tui/` imports `textual` or `textual_serve`.** `cli.py` imports
  them only inside the `tui` and `serve` code paths.
- **No test calls `claude`, Docker, Utopia or B-20.** Every collector takes injected callables, and
  tests pass fakes. The one real subprocess in tests is `tests/preflight/fixtures/fake_probe.py`.
- **Records are write-once; `notes.md` is append-only.** Never open either for rewriting.
- **Runtime markers are never stored** (§4.4). A record holds only the marker kinds; a saved probe

- **SQL names its columns.** No `select *` anywhere. `llm_settings.chat_api_key` and

- **Credentials are never printed or written,** and token files are read only by path through
  `contract_reader.client.bearer`.
- **The evidence deny-list** (§12): `dataset/answer-key`, `dataset/evaluation`, `truth`, `site`,
  `owm`, and any file named `MANIFEST.yaml`.
- **Versions:** `textual>=8.2,<9` and `textual-serve>=1.1,<2` in a new `tui` dependency group, and
  `[tool.uv] default-groups = ["dev", "tui"]`.
- **Commits:**

    staged diff; it must report 0 hits;
  - never write the scan's pattern into any file;
  - no amend, no force-push, no history rewrite;

## Rulings made in planning

Each was decided while writing this plan, where the spec was silent or a detail of the code forced
it.

- **P1. `probe.json`'s `expected_tools` may be `null`.**
  - *Why:* sor_reads' GD arm takes its tool names from `tools.yaml`.
  - *Effect:* the runner's own probe `problems` (its `check_probe`) are then binding, and pre-flight
    still records the tools in context.
- **P2. `agent_context.cap_usd` is added to the config** (required), because the probe's reservation
  needs a cap.
- **P3. Judge spend is counted from `*.judge.json`, or the newest `*.judge.infra-<k>.json` per
  snapshot when no `.judge.json` exists.**
  - *Why:* a resume renames the old file and carries its kept runs into the new one, so `*.judge*.json`
    (the spec's glob) would count them twice.
- **P4. B-20 counts are documents and facts, with facts summed per document.** Entities are omitted,
  because K1 lists entities only by query (`lab/exam/part1.py:124`).
- **P5. Drift can be accepted only when every other counted check passes.** Otherwise the record
  fails, no amendment is written, and the CLI says why.
- **P6. `Reservation.settle(cost_usd)` exists for a runner that writes its costs only at the end**
  (the judge). A settled reservation counts at its settled cost until it's released.
- **P7. Records are named by the time they're written, and the probe stream by the evaluation's
  start.**
  - *Why:* the app writes a `fail` record when an evaluation completes. Accepting drift writes a
    second, `accepted` record from the same evaluation, with no second probe.
- **P8. `--cap-usd` becomes required on the judge too** (§8 puts it under the guard).
- **P9. Utopia's base table is `knowledge_bases`, not `kbs`** (Utopia `migrations/0001_core.sql:53`).

## Review Focus

- **The first pre-flight in a fresh run folder** (no `preflight/` directory, no `notes.md`) works
  and sets the baseline. An accepted amendment creates `notes.md` if it's missing. *Tests: Task 2,
  Task 9.*
- **Evidence files that aren't valid UTF-8** (a Latin-1 CSV export) are read with replacement and
  never crash the inputs check. *Test: Task 5.*
- **A truncated probe stream** (the runner crashed: no init event, or no result event) fails agent
  context with a named problem. `recorded_usd` skips non-JSON lines. *Tests: Task 4, Task 8.*
- **Times in another zone:**
  - record names and attestation ages are computed in UTC from aware datetimes;
  - a local-time `datetime` passed in is converted to UTC, never used as-is.

  *Tests: Task 2, Task 6.*
- **Two pre-flights finishing in the same second** never overwrite each other: `write_record`
  refuses an existing name, and the engine retries with the next second. *Tests: Task 2, Task 9.*

- **The layout follows the spec's §9 mockup:**
  - a header line with the run and the baseline;
  - one row per check, marked `✔`, `✖`, `◌` (running) or `·` (n/a);

  - `confirm` is disabled while `Input.value.strip()` is empty;

    `finish(run, repo, self.evaluation, reason, deps)` in a thread worker (P7) and sets
    `"✔ ACCEPTED"`, or shows the outcome's note.
